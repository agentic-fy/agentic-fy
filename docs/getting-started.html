Getting Started

Install, initialize, and run your first change end to end.

Installation

agentic is a Node.js CLI. You need version 20.19.0 or newer. Check your Node:

node --version

Install the CLI globally:

npm install -g @agentic-fy/agentic

If you can't install globally (permission error under /usr/local), run it directly without installing:

npx @agentic-fy/agentic --version

Verify it worked

agentic --version

If it prints the logo and a version number, the CLI is on your PATH.

Your first five minutes

The whole loop:

$ npm install -g @agentic-fy/agentic
$ cd your-project && agentic init
$ agentic explore                    (optional: think it through first)
$ agentic propose add-dark-mode      (drafts the plan; you review it)
$ agentic apply                      (tracks the tasks)
$ agentic verify                     (checks it's ready)
$ agentic archive                    (change archived)
Not sure what to build yet? Start with agentic explore. It's a no-stakes thinking partner: it shows the project state and active changes, and helps turn a fuzzy idea into a concrete plan before any code is written.

What agentic creates

After running agentic init, your project gets this structure:

agentic.config.yaml     # project configuration
agentic/
├── specs/              # project specs
├── changes/            # proposed changes (one folder per change)
│   └── archive/        # completed changes

The init command creates only the base structure, idempotently: running it again does not overwrite the existing agentic.config.yaml.

When you create a change with propose, it looks like this:

agentic/changes/<change-name>/
├── proposal.md
├── design.md
├── tasks.md
├── specs/
│   └── spec.md
└── .agentic.yaml       # metadata (name, status, dates)

Understanding the artifacts

ArtifactPurpose
proposal.mdThe "why" and "what" — intent, scope, and approach
specs/spec.mdRequirements and acceptance criteria
design.mdThe "how" — technical approach and architecture decisions
tasks.mdImplementation checklist with checkboxes

Example: your first change

Let's add dark mode to an application.

1. Initialize the project

cd your-project
agentic init

2. Create the change

$ agentic propose add-dark-mode

[propose] add-dark-mode
Created: proposal.md
Created: design.md
Created: tasks.md
Created: specs/spec.md

3. Fill in the artifacts

Edit the files in agentic/changes/add-dark-mode/ and write the real tasks in tasks.md:

# Tasks — add-dark-mode

- [ ] 1. Create ThemeContext with light/dark state
- [ ] 2. Add a theme toggle to settings
- [ ] 3. Persist the preference in localStorage

4. Track the implementation

$ agentic apply

[apply] add-dark-mode
Applying change "add-dark-mode".
Tasks: 0 done, 3 pending.
  [ ] 1. Create ThemeContext with light/dark state
  [ ] 2. Add a theme toggle to settings
  [ ] 3. Persist the preference in localStorage

Implement the tasks and mark them as [x] in tasks.md as you go.

5. Verify

$ agentic verify

[verify] add-dark-mode
All artifacts present (proposal, design, tasks).
All tasks marked done.
Status updated to "verified".

6. Archive

$ agentic archive

[archive] add-dark-mode
Change "add-dark-mode" archived at agentic/changes/archive/add-dark-mode.

Letting the AI drive (MCP)

The commands above run in the terminal. To let your AI assistant drive the workflow, connect the MCP server:

agentic mcp

It exposes the explore, propose, apply, verify, and archive tools to any MCP-compatible agent. See the Commands page for setup in editors like Kiro.
